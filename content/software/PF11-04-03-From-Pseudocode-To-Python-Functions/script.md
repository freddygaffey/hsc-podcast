QUESTION: I write functions all day. What's the exam angle?

NARRATOR: Three things you can lose marks on even as a fluent coder: translating a pseudocode FUNCTION into a Python def precisely; knowing the three ways Python passes arguments and naming them; and the discipline of one job per function — plus the print-versus-return trap, which bites in exam code constantly. The headline task is "write a function, with parameters, that returns a given value." Let's make that bulletproof.

NARRATOR: Objectives up front. By the end you'll be able to: define a Python function and name its parts; translate a pseudocode subprogram to a def; pass arguments three ways — positional, default, and keyword; apply one-logical-task-per-function; and avoid returning nothing by accident. Let me start with the anatomy, because the exam marks the structure.

NARRATOR: A Python function starts with the keyword def — d-e-f, short for define — then the function's name, then parentheses holding its parameters, then a colon. Indented underneath comes the body, and ideally a docstring first — a triple-quoted line stating what the function does, exactly the function-contract documentation from the code-style episode. And the body ends, when it's a value-producing function, with a return statement that sends a value back to the caller. The full anatomy and the pseudocode-to-Python mapping are in Listing 1. The mapping is clean: pseudocode's FUNCTION name, parameters, RETURN value, END FUNCTION becomes def name, parameters, colon, and return value — the END FUNCTION vanishes, because, just like last episode, indentation marks where the function ends.

NARRATOR: And the function-versus-procedure distinction from Chapter Two carries straight over, with one Python wrinkle. In Python, everything is technically defined with def, but we keep the same terminology: a def that returns a value we call a function; a def that just performs an action and has no return statement we call a procedure — and here's the wrinkle, a Python function with no return statement doesn't return nothing in the void sense, it returns the special value None. Remember that — it's the mechanism behind today's trap. A function returns, a procedure performs; in Python a procedure quietly returns None.

NARRATOR: Let's translate one. Pseudocode: FUNCTION calculate-area, parameters length and width, set area to length times width, return area. The Python is almost identical: def calculate-area, length and width, colon, return length times width — you can even skip the temporary variable and return the expression directly. Listing 2 has that, plus a find-the-maximum-of-three function and a temperature converter from Celsius to Fahrenheit. The pattern for any "write a function" question: def, a descriptive name, the parameters it needs, a colon, the work, and a return of the result.

QUESTION: Here's one to actually attempt. Pause the player. Write a Python function called celsius-to-fahrenheit that takes a temperature in Celsius and returns it in Fahrenheit. The formula: multiply by nine, divide by five, add thirty-two. Work it out, then play.

NARRATOR: def celsius-to-fahrenheit, parameter celsius, colon; on the next line, indented, return celsius times nine divided by five plus thirty-two. That's it. The marks: the def with a sensible name, one parameter, and crucially a return — not a print — of the computed value, so the caller can use the result. Test it: zero Celsius returns thirty-two, a hundred Celsius returns two hundred and twelve. If you wrote print instead of return, you'd have built a procedure that shows the number but hands back None — and that's the trap, coming up.

NARRATOR: Now parameter passing — the dot-point literally says "incorporate parameter passing," and Python gives you three ways, which you should be able to name. The hook is P-D-K: Positional, Default, Keyword. Positional is the default: arguments match parameters by order, so the first argument fills the first parameter. Order matters — a format-name function called with the first and last name swapped gives the wrong result, no error, just wrong. Default parameters give a parameter a fallback value, used when the caller omits it — a greet function with a greeting parameter defaulting to "Hello" works with just a name, or with a custom greeting supplied. The rule: default parameters must come after non-default ones, or it's a syntax error. And keyword arguments let the caller name the parameter at the call site — so you can pass them in any order, and the code reads clearly. Listing 3 demonstrates all three. P-D-K: Positional, Default, Keyword.

NARRATOR: Then the design discipline, and it's the cohesion idea from the structure-charts episode applied to functions: one logical task per function. This is called the single-responsibility principle — a function should do one thing well. Listing 4 shows the contrast. The bad version is a single process-student function that calculates the average, determines the grade, formats a report, and saves to a file — four jobs in one, low cohesion, hard to test or reuse. The good version splits them: calculate-the-average, determine-the-letter-grade, format-the-report, save-the-record — each one job, each independently testable, each reusable — and a small coordinator function that calls them in turn. If you can't name a function in a short verb phrase, it's doing too much. High cohesion, one function, one job.

NARRATOR: And the trap, straight from Chapter Two and worth repeating because it's the most common function bug in exam code: printing inside a function when you meant to return. A function that prints its result shows the number on screen but returns None, so the caller gets nothing usable — and the next line that tries to use the result breaks. Listing 5 puts the broken print version next to the correct return version. The rule to state for the mark: if the caller needs the value, return it; printing is a display action, a procedure's job. Return to reuse; print only to show.

NARRATOR: Consolidate — takeaways, the way you'd write them. One: a Python function is def, a name, parameters in parentheses, a colon, an indented body, and a return — the END FUNCTION of pseudocode becomes indentation. Two: a def that returns a value is a function; one with no return is a procedure and quietly returns None. Three: arguments pass three ways — P-D-K, Positional by order, Default fallbacks, and Keyword by name; defaults come after non-defaults. Four: one logical task per function — single responsibility, which is high cohesion. Five: return the result if the caller needs it — printing returns None. Watch the traps: print instead of return, forgetting return entirely, a default parameter before a non-default, and positional arguments in the wrong order.

NARRATOR: Now the exam-style questions. Pen down, and when I say pause, attempt it before the model answer.

QUESTION: Question one. Write a Python function named calculate-tax that takes an amount and a tax rate and returns the tax owed. Pause the player, write it, then play.

NARRATOR: def calculate-tax, parameters amount and rate, colon; on the next line, indented, return amount times rate. The marks: the def with a clear name, two parameters, and a return of the product — not a print. A nice touch for a fuller answer is a default rate, say zero-point-one for ten percent, so it can be called with just an amount; if you do, the default must come after the non-default amount. The essential mark is that it returns the value.

QUESTION: Question two. Distinguish between positional arguments and keyword arguments.

NARRATOR: Positional arguments are matched to parameters by their order in the call — the first argument fills the first parameter, and so on, so order is critical. Keyword arguments are matched by naming the parameter explicitly at the call site, so their order doesn't matter and the call is more readable. The distinguishing point: positional binds by position, keyword binds by name. The mark is that contrast, ideally with the note that keyword arguments can be given in any order.

QUESTION: Question three. Explain the purpose of a default parameter value, and state the rule about where default parameters may appear.

NARRATOR: A default parameter value lets a function be called without supplying that argument — the default is used when the caller omits it, making the parameter optional and the common case simpler to call. The rule is that parameters with defaults must come after all parameters without defaults in the function definition; placing a default before a non-default is a syntax error. The marks: the "optional with a fallback" purpose, and the after-non-defaults ordering rule.

QUESTION: Question four. A student writes a function to compute a discounted price but uses print inside it instead of return, then tries to use the result. Explain what goes wrong.

NARRATOR: Because the function prints rather than returns, it produces output on screen but returns the value None to the caller. When the student assigns the call's result to a variable and uses it, that variable is None, so the subsequent calculation fails or is wrong — even though the price appeared correctly on screen. The fix is to return the value so the caller can use it, adding a separate print only if display is also wanted. The phrasing that scores: "a function with no return statement returns None; to reuse a result, return it rather than print it."

QUESTION: Question five. The following function does too much: it calculates an average, assigns a grade, and prints a report. Rewrite it as well-structured functions.

NARRATOR: Split it by responsibility into three functions: calculate-the-average, which takes the scores and returns the mean; determine-the-letter-grade, which takes the average and returns a letter; and a procedure to display or format the report, which takes the name, average, and grade. Then a small coordinating function calls the three in order. Each has a single responsibility, so each is independently testable and reusable, and the whole has high cohesion and low coupling. The marks: the decomposition into single-purpose subprograms, correct use of return for the calculating ones, and naming the single-responsibility principle.
