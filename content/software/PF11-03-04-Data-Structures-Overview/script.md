NARRATOR: First, arrays. An array is an ordered collection of items, accessed by their position — an index — and the index starts at zero. In Python you use a list for this. A single-dimensional array is a simple sequence: a row of grades, a shopping list. You reach any item by its index — item zero is the first, item one is the second — and a sharp exam point that's also the number-one trap: the index starts at zero, so the first element is at index zero and the fifth is at index four. Off-by-one errors live here.

NARRATOR: Arrays also come multi-dimensional. A two-dimensional array is a table — rows and columns — and you build it as a list of lists: each inner list is a row. The classic is a grade book: each row is a student, each column is a subject. You access a cell with two indices, row first then column — so row zero, column one is the first student's second subject. Listing 1 builds a grade book and reads cells out of it, and it sums every grade with a nested loop — an outer loop over the rows, an inner loop over the columns — which is exactly the nested iteration from the control-structures episode, doing real work. Because that traversal is examinable as an algorithm, Listing 2 gives it in NESA pseudocode: two nested for-loops, the outer over rows, the inner over columns. When you use a two-dimensional array, you almost always pair it with a nested loop.

NARRATOR: When do you use an array? Whenever you have an ordered collection of similar items that you access by position — and a two-dimensional one when the data is naturally a table or grid: a spreadsheet, a game board, a seating chart. That's the key character of an array: many items of the same kind, reached by a number.

NARRATOR: Second, records. And here's the distinction the exam loves, so hold the contrast in your head. Where an array holds many items of the same kind indexed by a number, a record groups related fields of different kinds, accessed by name. A student record bundles a name, which is a string, an age, which is an integer, and a grade average, which is a float — different types, one entity, each field reached by its name, not a number. This is exactly the entity your data dictionary described last episode: the dictionary specifies the fields and their rules; the record is the actual bundle of values. In Python you can model a record with a dictionary — keys are the field names, values are the data. Listing 3 shows a single student record and then a whole class roster as a list of records — a list, whose items are records. That combination, a collection of records, is how most real data is shaped.

QUESTION: Here's one to actually attempt. Pause the player. You're storing the marks of thirty students across five subjects, and separately, the full profile of one student — name, age, email, enrolment status. Which structure for each, and why? Work it out, then play.

NARRATOR: The marks of thirty students across five subjects: a two-dimensional array — a table, thirty rows by five columns, all the same kind of data, a number, accessed by position. The profile of one student: a record — related fields of different types, name and age and email and status, accessed by name. The justification is the mark: same-kind data indexed by position is an array; mixed related fields of one entity accessed by name is a record. Naming that distinction is what earns it.

NARRATOR: Third, trees. A tree is a hierarchical structure — it starts at a root and branches out, like a family tree or an organisation chart. The vocabulary: the top is the root; each item is a node; a node's branches lead to its children; a node with no children is a leaf. Note the convention — in computing a tree is drawn upside down, root at the top, leaves at the bottom. What makes a tree different from an array or a list is that it's not linear — it branches, capturing parent-child relationships that a flat sequence can't. When do you use one? For anything hierarchical: a family tree, an organisation chart, a computer's file system of folders within folders, a decision tree. Listing 4 builds a small family tree and counts everyone in it with a recursive traversal — a function that counts the current node, then calls itself on each child. That recursion is the divide-and-conquer idea from the design episode: a tree is naturally divided into subtrees, each handled the same way. Trees and recursion go together.

NARRATOR: Fourth, sequential files. Everything so far lives in memory and vanishes when the program ends. A file persists data on disk. A sequential file stores data as a sequence — records one after another — read from the start to the end in order, like reading lines down a page. The common format you'll meet is C-S-V, comma-separated values: each line is a record, fields separated by commas, the first line often a header naming the columns. It's the standard way to store and exchange tabular data — export a spreadsheet, hand data to another program. Listing 5 writes a few student records to a comma-separated format and reads them back in order. The defining feature, and a likely distinguish point: a sequential file is read in order, front to back — contrast that with direct or random access, where you jump straight to any record by position. Sequential is the page you read top to bottom; random access is the dictionary you flip straight open.

NARRATOR: So that's A-R-T-S — arrays, records, trees, sequential files. And the headline exam skill is choosing among them with justification. Listing 6 is a quick-reference table — need an ordered collection by position, use an array; a table or grid, a two-dimensional array; related fields of one entity, a record; a hierarchy, a tree; data that must survive in a file, a sequential file. QUESTION: How does the exam phrase the choosing question, and what's the trap?

NARRATOR: It gives a scenario — "a program needs to represent the folder structure of a hard drive" — and asks you to choose a structure and justify it. Answer: a tree, because a file system is hierarchical, with folders containing folders and files, which a tree's parent-child branching models naturally and a flat list cannot. That last clause is the key: say why the alternatives fail. And the trap, the one the markers watch for, is treating every collection as a flat list. Reaching for a one-dimensional list when the data is really a table, a hierarchy, or a set of named fields is the classic mistake — the shape of your structure should match the shape of your data. A grade book isn't a flat list; it's a table. A file system isn't a flat list; it's a tree.

NARRATOR: Now the exam-style questions. Pen down, and when I say pause, attempt it before the model answer.

QUESTION: Question one. Name the four data structures from this dot-point, and state when each is used.

NARRATOR: Arrays — ordered collections of similar items accessed by position, including two-dimensional arrays for tables. Records — groups of related fields of different types accessed by name, for modelling one entity. Trees — hierarchical structures of nodes from a root, for parent-child relationships. Sequential files — data stored on disk as an ordered sequence of records, for persisting and exchanging data. The hook is A-R-T-S, and the "used for" clause on each is what turns recall into a clear answer.

QUESTION: Question two. Distinguish between an array and a record. Pause the player, write your answer, then play.

NARRATOR: An array stores many items of the same kind in order, each accessed by a numeric index starting at zero. A record stores related fields of potentially different types describing one entity, each accessed by its field name. The distinguishing contrast: an array is indexed by position and holds homogeneous items; a record is accessed by field name and holds heterogeneous, related fields. Full marks come from that explicit contrast — number-and-same-kind versus name-and-mixed — not two separate definitions.

QUESTION: Question three. A program must represent a company's organisation chart, where each manager has several direct reports. Choose a suitable data structure and justify your choice.

NARRATOR: A tree. An organisation chart is hierarchical — one person at the top, each manager with several reports who may themselves have reports — which is exactly the root-and-branching parent-child structure a tree represents. A flat list couldn't capture who reports to whom, and a single array couldn't show the levels. The marks are for naming the tree, justifying with the hierarchy, and noting why a flat structure fails.

QUESTION: Question four. In a two-dimensional array used as a grade book, with students as rows and subjects as columns, which indices access the third student's second subject? Explain the off-by-one consideration.

NARRATOR: Row index two, column index one. Because array indices start at zero, the third student is at row index two — zero, one, two — and the second subject is at column index one. The off-by-one consideration is precisely that: a count of "third" and "second" maps to indices two and one, not three and two, because counting starts at zero. Confusing the human count with the zero-based index is the classic off-by-one error.

QUESTION: Question five. Distinguish a sequential file from random (direct) access, and name a common sequential file format.

NARRATOR: A sequential file is read or written as an ordered sequence, from the beginning through to the end, processing one record after another. Random, or direct, access allows jumping straight to any record by its position or key without reading the ones before it. The contrast: sequential processes records in order start-to-finish; random access reaches any record directly. A common sequential file format is comma-separated values, C-S-V. The mark is the in-order versus jump-directly distinction, plus naming the format.
