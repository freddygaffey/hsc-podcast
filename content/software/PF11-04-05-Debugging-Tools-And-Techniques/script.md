NARRATOR: Now the IDE debugger — the dot-point's "debugging software available in an IDE" — and its three core tools, the ones the exam wants you to describe. They're in Listing 5, and here's the memory hook: the debugger trio is Breakpoint, Step, Watch — pause, walk, watch. A breakpoint is a marker you set on a line; when you run in debug mode, execution pauses there, so you can inspect the program's state at that exact moment — the values of all the variables, frozen. Breakpoint to pause, step to walk, watch to watch.

QUESTION: Question one. Name the three types of programming error and state how each reveals itself.

NARRATOR: A syntax error breaks the language's rules, so the program won't run at all and the interpreter reports it before execution. A runtime error occurs during execution, crashing the program with an exception and usually a line number. A logic error doesn't crash — the program runs to completion but produces an incorrect result, with no error message. The mark is naming all three and the giveaway for each: won't run, crashes, or runs-but-wrong. The logic error being silent is the key point.

QUESTION: Question two, four marks. Describe how a breakpoint and a watch help a programmer locate a bug. Pause the player, write your answer, then play.

NARRATOR: A breakpoint is a marker set on a specific line that pauses execution when reached, allowing the programmer to inspect the program's state — the current values of variables — at that exact point. A watch displays the live value of a chosen variable and updates it whenever the variable changes, so the programmer can see precisely when it takes an incorrect value. Together, the programmer sets a breakpoint near the suspected fault and, while paused, single-steps through the code watching the key variable, pinpointing the line where it becomes wrong. Four marks: what a breakpoint does, what a watch does, and how they're used together to locate the fault.

QUESTION: Question three. Distinguish between a breakpoint and single-line stepping.

NARRATOR: A breakpoint pauses execution at a chosen line, stopping the program so its state can be inspected at that point. Single-line stepping then executes the program one line at a time from a paused point, letting the programmer observe the effect of each individual line as it runs. The distinguishing point: a breakpoint is where execution stops; single-stepping is how you move forward, one line at a time, after it has stopped. They work together — breakpoint to pause, step to advance.

QUESTION: Question four. A factorial function uses the range function over just n and returns zero for all positive inputs. Identify the cause and the fix.

NARRATOR: The cause is that the range function with a single argument n produces the values zero up to n minus one, starting at zero. The factorial multiplies its running result by each value, so the first multiplication is by zero, which makes the result zero and keeps it zero for every subsequent multiplication. The fix is to loop with the range function from one to n-plus-one, so the loop variable runs from one to n and never includes zero. The mark-earning phrasing: "the range starts at zero, so the result is multiplied by zero on the first iteration; use range from one to n-plus-one." It's a logic error — the code runs without crashing, it's just wrong.

QUESTION: Question five. What does it mean to check the "interfaces between functions" when debugging, and why is it useful?

NARRATOR: Checking the interfaces between functions means examining the values passed into a function as arguments and the value it returns — the data crossing the boundary between one function and another. It's useful because many bugs are not inside a function's logic but in what is handed to it or returned from it: a wrong argument, arguments in the wrong order, or a None returned because a function printed instead of returning. By inspecting the inputs and outputs at each function boundary, the programmer can quickly tell whether a function received correct data and produced correct data, isolating which function is at fault. The mark is defining the interface as the arguments-in and value-out, and the use as isolating which function is wrong.
