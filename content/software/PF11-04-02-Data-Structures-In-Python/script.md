NARRATOR: First, arrays. In Python the list is the array — an ordered, indexed, growable sequence. The classic processing pattern the exam uses is find the maximum and its position: you walk the list with an index, tracking the best value and where you found it. Listing 1 does that, plus the two-dimensional case — a grade book as a list of lists, where you reach a cell with two indices, row then column, and compute each student's average by processing a row. And the trap that never goes away: indices start at zero, so the third element is at index two. Off by one lives here.

NARRATOR: Second, lists and their operations — and this is where you should just know the vocabulary cold, because exam code uses it. Append adds to the end. Insert adds at a given position. Remove deletes the first matching value. Pop removes and returns an element — the last one by default, or one at a given index. Index finds the position of a value. The "in" keyword tests membership. And the length function gives the count. Listing 2 runs through all of them on one list so you can see the state after each step. Nothing exotic — but naming the right method in a written-code answer is the mark.

NARRATOR: Third, and this is the headline: stacks. A stack is the first structure the syllabus names that Python has no built-in type for — so you implement it with a list. A stack is a last-in, first-out structure — abbreviated L-I-F-O — like a stack of plates: you add to the top, and you remove from the top, so the last thing you put on is the first thing you take off. The two operations have traditional names: push, to add an item to the top, and pop, to remove the top item. The implementation is beautifully simple, because a Python list already has the right methods — push is just append, adding to the end, and pop is the list's pop, removing from the end. The end of the list is the top of the stack. Listing 3 wraps this in a small stack with push, pop, a peek to look at the top without removing it, and an is-empty check; and Listing 4 gives the same in NESA pseudocode, because stack operations are examinable as algorithms. Push three items, A then B then C, and pop — you get C first, then B, then A. Last in, first out.

QUESTION: Here's one to actually attempt. Pause the player. Using a Python list, write the push and pop operations for a stack, and say what pop returns after you push the values one, two, three. Work it out, then play.

NARRATOR: Push is the list's append method — add the item to the end. Pop is the list's pop method — remove and return the last element. After pushing one, two, three, the list is one, two, three, and pop returns three — the last in is the first out. Pop again gives two, then one. The mark for "implement a stack" is exactly this: append for push, pop for pop, and the statement that it's last-in-first-out. And the trap: pop with no argument removes from the end, the top — not the front. If you popped from the front you'd have a queue, which is first-in-first-out, the opposite. A stack is L-I-F-O; a queue is F-I-F-O. That distinction is a common question.

NARRATOR: Where do stacks show up, so it sticks? Three real places, and they connect to earlier episodes. An undo function — each action pushed on a stack, undo pops the most recent. The program's own call stack — when one function calls another, the return addresses stack up, last call returns first. And backtracking, from the design-strategies episode — try, fail, undo, retry is a stack of choices you pop when you hit a dead end. The stack is everywhere once you see it.

NARRATOR: Fourth, hash tables. A hash table maps keys to values and looks them up fast — and in Python it's simply the dictionary. The name "hash table" describes how it works under the hood: it hashes the key to compute where the value is stored, so lookup is near-instant regardless of size, unlike searching a list element by element. A phone book is the mental model: you don't scan every entry, you go straight to the name. You use a dictionary whenever you need fast lookup by a unique key, and a second classic use is counting — tallying how many times each item appears, using the item as the key and the count as the value. Listing 5 shows both: a phone book with instant lookup, and a letter-frequency counter. The exam phrasing: a hash table gives fast, near-constant-time lookup by key, which a list can't.

NARRATOR: Fifth, trees, briefly — we met these conceptually two episodes ago, and the Python implementation is the nested dictionary: a node is a dictionary with a value and a list of child nodes, each child the same shape. Listing 6 builds a family tree and counts everyone with a recursive function — count this node, then add the counts of all its children. That recursion is the divide-and-conquer idea: a tree splits into subtrees, each handled the same way. Trees and recursion travel together.

NARRATOR: Now the exam-style questions. Pen down, and when I say pause, attempt it before the model answer.

QUESTION: Question one. Implement a stack using a Python list, with push and pop operations, and explain the order items are removed. Pause the player, write it, then play.

NARRATOR: Keep a list as the stack. Push appends the item to the end of the list. Pop calls the list's pop method, which removes and returns the last element. Items are removed in last-in, first-out order: the most recently pushed item is the first popped, because both operations work at the end of the list, which represents the top of the stack. Full marks: append for push, pop for pop, and the explicit last-in-first-out statement with the reason — both operate on the same end.

QUESTION: Question two. Distinguish between a stack and a queue, giving the order of removal for each.

NARRATOR: A stack is last-in, first-out: the most recently added item is removed first, like a stack of plates. A queue is first-in, first-out: the earliest added item is removed first, like a line of people. The distinguishing point is the removal order relative to insertion order — a stack removes from the same end it adds to, a queue removes from the opposite end. The mark is naming both orders, L-I-F-O and F-I-F-O, with a one-line reason or example.

QUESTION: Question three. Which Python data type implements a hash table, and state one advantage over a list for looking up a value.

NARRATOR: The dictionary implements a hash table. Its advantage over a list is fast lookup: a dictionary retrieves a value by its key in near-constant time, regardless of how many entries it has, whereas finding a value in a list generally requires searching element by element, which gets slower as the list grows. The mark is naming the dictionary and the fast-lookup-by-key advantage, ideally with the contrast that a list must be searched sequentially.

QUESTION: Question four. Given a two-dimensional list used as a grade book with students as rows and subjects as columns, write code to compute the average for the first student.

NARRATOR: Take the first row — index zero — which holds that student's subject marks, and compute the sum of that row divided by its length. In Python: the average equals the sum of grade-book at index zero, divided by the length of grade-book at index zero. That processes one row to get one student's average. The marks are for indexing the correct row with index zero and dividing the row's sum by the number of subjects — and the off-by-one awareness that the first student is row zero.

QUESTION: Question five. A program needs an "undo" feature that reverses the most recent action first. Which data structure is appropriate and why?

NARRATOR: A stack. Each action is pushed onto the stack as it happens, and undo pops the stack, which returns the most recent action first — exactly the last-in, first-out behaviour an undo feature needs, since you undo the latest change before earlier ones. The mark is naming the stack and justifying with last-in-first-out matching the "most recent first" requirement.
