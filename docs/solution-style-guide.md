# Solution style guide (Maths)

> How every worked solution in the bank should be formatted — whether it's cleaned up from a
> paper's own solutions or [AI-generated](../.claude/skills/parse-papers/) to fill a gap.
> The goal is that a student can't tell which school a solution came from: one consistent house
> style. Draft — iterate freely.

Grounded in the real corpus: the best school solutions (e.g. Baulkham Hills) are already a clean
step-per-line table with typeset math and the MC letter called out; the worst are handwritten
scrawl in the margin (James Ruse). We standardise on the former, rendered digitally.

## 1. Math — rendered LaTeX, always

- **All** mathematics is LaTeX, rendered (KaTeX in-app; compiled to SVG for static/PDF). Never
  plain-text math (`x^2`, `sqrt`), never an image of an equation.
- Inline quantities: `\( ... \)`. Standalone steps: display `\[ ... \]` or `align*`.
- **One logical step per line.** Multi-step working uses `align*` aligned on the relation:
  ```latex
  \begin{align*}
    2b + b + 4b + 5b &= 1 \\
    12b &= 1 \\
    \therefore\ b &= \tfrac{1}{12}
  \end{align*}
  ```
- Conventions: `\dfrac` (display) / `\tfrac` (inline) for fractions; `\therefore` for a
  conclusion; `\times` not `x` or `*`; real symbols (`\theta`, `\pi`, `\sigma`, `\bar{x}`);
  units in upright text `\,\text{m}`; intervals `(-\infty, 4) \cup (4, \infty)`.
- **Final answer boxed:** `\boxed{\;\bar{x} = 19.73\;}`.
- Show *relevant mathematical reasoning* (the papers' own instruction) — enough working to earn
  every mark, no more. Method first, arithmetic second.

## 2. Graphs & diagrams — Python + matplotlib

- Every graph, plot, number plane, box-plot, or geometry figure is **generated by matplotlib**
  — not hand-drawn, not a scanned image, not TikZ. Output **SVG** (crisp at any zoom), embedded.
- One shared house style so every figure matches. Baseline `rcParams`:
  ```python
  import matplotlib.pyplot as plt
  plt.rcParams.update({
      "figure.figsize": (4.2, 3.2), "figure.dpi": 140,
      "font.family": "STIXGeneral", "mathtext.fontset": "stix",  # matches LaTeX body
      "axes.spines.top": False, "axes.spines.right": False,
      "axes.grid": True, "grid.alpha": 0.25, "font.size": 11,
  })
  ```
- HSC conventions on graphs: arrowheads on axes, label axes (`x`, `y`), mark and annotate key
  features (intercepts, turning points, asymptotes as dashed), equal aspect for geometry.
- Keep data exact — plot from the actual function/values in the solution, not eyeballed.

## 3. Structure of one solution

- Mirror the question's part labels: **(a)**, **(b)(i)**, … in the same order. Never restate the
  question text (it's shown beside the solution).
- **Multiple choice:** lead with the answer, then justify:
  > **C.** \( A=-3,\ B=2 \) — the graph is reflected (\(A<0\)) with period \(\pi\Rightarrow B=2\).
- **Marks:** where a part is worth >1 mark, the working should visibly reach each mark's step
  (method mark → answer mark), matching the paper's allocation.
- End every part with the boxed final answer.

## 4. AI-generated solutions — watermark (mandatory)

When a solution is synthesised (no real solution exists — see the
[solution-coverage requirement](../.claude/skills/projects)):

- A **visible diagonal watermark** "AI-GENERATED SOLUTION" behind the content (light grey,
  ~15% opacity, 30°), plus a one-line header badge "⚠ AI-generated — not from an official
  marking scheme."
- Watermark is applied at render/bake time and can never be confused with a real solution.
- **Real solutions are never watermarked.** A watermarked solution is always synthetic.

## 5. House style (consistency)

- Body text and math share one font family (STIX / a LaTeX-matching face) so inline math doesn't
  jump. Left-aligned, generous line spacing, one step per line.
- Colour is functional only: ink for working, one accent for the boxed answer / key annotations;
  legible in both light and dark. No decorative colour.
- Same figure size and margins everywhere; solutions read as one series, not a patchwork.
